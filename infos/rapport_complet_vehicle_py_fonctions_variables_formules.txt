0. BUT DU FICHIER vehicle.py
===============================================================================

Le fichier vehicle.py est le coeur comportemental du simulateur. Il ne dessine
pas la carte et ne cree pas les routes : il decide comment les voitures vivent
dans le reseau.

Il gere :
- la creation des vehicules ;
- le choix de leur chemin ;
- leur vitesse ;
- leur position GPS ;
- leur etat visuel/logique ;
- la distance de securite ;
- les files d'attente aux feux ;
- l'arret au rouge/orange ;
- le redemarrage au vert ;
- les priorites d'intersection ;
- les conflits entre trajectoires ;
- les routes sens unique et double sens ;
- la protection contre les chevauchements ;
- les statistiques pour l'affichage ;
- les donnees pour les futurs feux intelligents.

Le fichier depend principalement de :
- graph.py : fournit RoadGraph, GraphNode, GraphEdge et haversine ;
- traffic_light_manager.py : fournit TrafficLightManager et LightState.

2. CONSTANTES GLOBALES

VEHICLE_LENGTH = 4.5
--------------------
Longueur theorique d'un vehicule, en metres.
Utilisee pour garder de l'espace entre deux voitures.

SAFE_GAP = 5.0
--------------
Distance minimale de securite devant une voiture.
Si l'espace devant est inferieur ou egal a SAFE_GAP, la vitesse cible devient 0.

BRAKE_DISTANCE = 35.0
---------------------
Distance a partir de laquelle une voiture commence a adapter sa vitesse au
vehicule devant elle.

QUEUE_SLOT = VEHICLE_LENGTH + 2.0
---------------------------------
Place reservee a une voiture dans une file.
Formule :
    QUEUE_SLOT = VEHICLE_LENGTH + 2.0
Avec les valeurs actuelles :
    QUEUE_SLOT = 4.5 + 2.0 = 6.5 m

QUEUE_JOIN_DIST = 80.0
----------------------
Distance maximale a laquelle une voiture peut rejoindre une file de feu.
Au-dela, elle ralentit eventuellement mais ne se declare pas encore dans la file.

STOP_LINE_DIST = 4.0
--------------------
Distance de la ligne d'arret par rapport au noeud du feu ou de l'intersection.
La premiere voiture doit s'arreter environ 4 m avant le noeud.

LIGHT_BRAKE_DIST = 50.0
-----------------------
Distance de freinage progressif avant un feu rouge/orange.

INTER_RESERVE_DIST = 20.0
-------------------------
Distance a partir de laquelle une voiture commence a demander une reservation
d'intersection.

INTER_CLEAR_DIST = 3.0
----------------------
Distance tres proche du carrefour. Si une voiture doit ceder et qu'elle est dans
cette zone, elle doit quasiment s'arreter.

INTER_YIELD_TIMEOUT = 8.0
-------------------------
Temps maximum d'attente avant de forcer une reservation si aucun conflit direct
n'existe. Cela evite certains blocages prolonges.

MAX_ACCEL = 2.5
---------------
Acceleration maximale, en m/s^2.
Formule d'acceleration :
    nouvelle_vitesse = vitesse + MAX_ACCEL * dt

MAX_DECEL = 5.5
---------------
Deceleration maximale, en m/s^2.
Formule de freinage :
    nouvelle_vitesse = vitesse - MAX_DECEL * dt

MIN_SPEED = 0.1
---------------
Seuil sous lequel une vitesse est consideree comme nulle.
Si speed < MIN_SPEED, le vehicule est mis a 0 et son etat devient STOPPED.

MAX_SEGS_PER_TICK = 5
---------------------
Nombre maximum de segments qu'une voiture peut traverser pendant une seule mise
a jour. C'est une securite contre les sauts anormaux a vitesse de simulation
elevee.

QUEUE_RELEASE_COOLDOWN = 2.0
----------------------------
Temps de protection apres sortie d'une file. Pendant ce temps, la voiture ne
rejoint pas immediatement une autre file.

CONGESTION_VEHICLE_PENALTY = 2.0
--------------------------------
Penalite ajoutee au calcul d'itineraire pour chaque vehicule deja present sur un
segment.

CONGESTION_BRAKING_PENALTY = 4.0
--------------------------------
Penalite supplementaire si un vehicule sur le segment est en freinage ou roule
tres lentement.

CONGESTION_STOPPED_PENALTY = 7.0
--------------------------------
Penalite supplementaire si un vehicule est arrete.

CONGESTION_QUEUE_PENALTY = 6.0
------------------------------
Penalite supplementaire quand une voiture est en file au feu, ou quand une file
existe deja sur un segment.

CONGESTION_ROAD_FACTOR = 0.25
-----------------------------
Facteur applique aux penalites de route entiere. Cela propage une partie de la
congestion a tous les arcs de la meme route, sans bloquer totalement la route.

RECEIVING_SEGMENT_FILL_RATIO = 0.85
-----------------------------------
Taux de remplissage maximum accepte avant d'interdire l'entree dans le segment
suivant.
Si un segment est deja rempli a environ 85 %, la voiture attend avant le noeud.

M_PER_DEG_LAT = 111_320.0
-------------------------
Conversion approximative d'un degre de latitude en metres.

M_PER_DEG_LON = 111_320.0 * cos(radians(48.85))
------------------------------------------------
Conversion approximative d'un degre de longitude en metres a Paris.
La longitude doit etre multipliee par cos(latitude), parce qu'un degre de
longitude ne vaut pas la meme distance selon la latitude.

Formule :
    M_PER_DEG_LON = 111_320 * cos(48.85 degres)

5. FONCTIONS GLOBALES
===============================================================================

5.1 _seg_dir_meters(fn, tn)
---------------------------
Role :
Calcule le vecteur unitaire du segment fn -> tn en metres.

Parametres :
- fn : noeud de depart ;
- tn : noeud d'arrivee.

Variables :
- dx : difference de longitude transformee en metres ;
- dy : difference de latitude transformee en metres ;
- n : norme du vecteur ;
- ux : composante horizontale normalisee ;
- uy : composante verticale normalisee.

Formules :
    dx = (tn.lon - fn.lon) * M_PER_DEG_LON
    dy = (tn.lat - fn.lat) * M_PER_DEG_LAT
    n = sqrt(dx * dx + dy * dy)
    ux = dx / n
    uy = dy / n

Retour :
    (ux, uy, True)
ou
    (0.0, 0.0, False)

Cas de securite :
- si fn ou tn vaut None, retour invalide ;
- si n < 1e-6, le segment est trop court, retour invalide.

5.2 _dot_to_other_meters(v, other, ux, uy)
------------------------------------------
Role :
Dire si other est devant ou derriere v dans la direction (ux, uy).

Parametres :
- v : voiture de reference ;
- other : autre voiture ;
- ux, uy : direction de la voie.

Variables :
- dx : distance Est-Ouest entre v et other ;
- dy : distance Nord-Sud entre v et other.

Formule :
    resultat = dx * ux + dy * uy

Interpretation :
- resultat > 0 : other est devant v ;
- resultat < 0 : other est derriere v ;
- resultat proche de 0 : other est sur le cote ou au meme niveau.

5.3 _speed_for_gap(gap, max_speed)
----------------------------------
Role :
Transformer une distance libre en vitesse cible.

Parametres :
- gap : espace disponible devant la voiture ;
- max_speed : vitesse maximale autorisee.

Regles :
- si gap <= SAFE_GAP, retour 0 ;
- si gap >= BRAKE_DISTANCE, retour max_speed ;
- sinon vitesse proportionnelle.

Formule :
    max_speed * (gap - SAFE_GAP) / (BRAKE_DISTANCE - SAFE_GAP)

Sens de la formule :
- plus gap est proche de SAFE_GAP, plus la vitesse est proche de 0 ;
- plus gap est proche de BRAKE_DISTANCE, plus la vitesse est proche de max_speed.

5.4 _apply_speed(v, desired, dt)
--------------------------------
Role :
Modifier progressivement la vitesse actuelle pour tendre vers desired.

Parametres :
- v : vehicule ;
- desired : vitesse cible ;
- dt : temps simule depuis la derniere mise a jour.

Cas 1 : desired <= 0
La voiture freine vers 0.
Formule :
    v.speed = max(0.0, v.speed - MAX_DECEL * dt)
Si v.speed < MIN_SPEED :
    v.speed = 0
    v.state = STOPPED
Sinon :
    v.state = BRAKING

Cas 2 : v.speed < desired
La voiture accelere.
Formule :
    v.speed = min(desired, v.speed + MAX_ACCEL * dt)
Etat :
    MOVING

Cas 3 : v.speed > desired
La voiture ralentit.
Formule :
    v.speed = max(desired, v.speed - MAX_DECEL * dt)
Etat :
    BRAKING

Cas 4 : v.speed == desired
La voiture garde sa vitesse.
Etat :
    MOVING

7.2 build_edge_index()
----------------------
Role :
Precalculer :
- les routes a sens unique ;
- les entrees de chaque noeud.

Variables locales :
- existing : ensemble des arcs existants sous forme (road_id, from, to) ;
- road_fwd : pour chaque route, liste des arcs dans le sens lu ;
- rid : identifiant de route ;
- pairs : couples (from, to) d'une route ;
- ow : nombre de routes sens unique ;
- tw : nombre de routes double sens.

Principe sens unique :
Pour chaque arc (fn, tn), le code cherche si l'arc inverse (tn, fn) existe sur
la meme route.

Formule logique :
    route_sens_unique = all((rid, tn, fn) not in existing for (fn, tn) in pairs)

Si tous les arcs inverses sont absents, la route est consideree comme sens
unique.

Principe incoming_cache :
Pour chaque edge from -> to :
    _incoming_cache[to].add(from)

7.3 spawn_vehicle(origin_node=None, dest_node=None)
---------------------------------------------------
Role :
Creer un vehicule avec un chemin valide.

Variables :
- pool : noeuds possibles pour creer des voitures ;
- o : origine choisie ;
- d : destination choisie ;
- path : chemin calcule par Dijkstra ;
- on : noeud origine ;
- vid : identifiant du vehicule ;
- color : couleur aleatoire ;
- v : objet Vehicle cree.

Etapes :
1. Prend les noeuds de spawn.
2. Choisit origine/destination, avec au maximum 20 essais.
3. Refuse si origine = destination.
4. Calcule le chemin :
       graph.dijkstra(o, d, self._make_congestion_penalty())
5. Cree le vehicule.
6. Initialise son segment.
7. Verifie que le spawn est libre.
8. Ajoute le vehicule.

Point important :
Le chemin utilise maintenant une penalite de congestion. Donc les nouveaux
vehicules evitent mieux les routes deja saturees.

7.4 spawn_batch(count)
----------------------
Role :
Creer plusieurs vehicules.

Variables :
- ok : nombre de creations reussies.

Boucle :
Pour count tentatives, appelle spawn_vehicle.
Si le retour n'est pas None, ok augmente.

7.5 _make_congestion_penalty()
------------------------------
Role :
Creer une fonction de penalite transmise a Dijkstra.

Variables :
- edge_penalties : penalites par arc (seg_from, seg_to) ;
- road_penalties : penalites par route complete ;
- vehicle : vehicule inspecte ;
- penalty : penalite calculee pour ce vehicule ;
- key : couple (seg_from, seg_to) ;
- light_nid : feu d'une file ;
- seg_from : origine d'approche de la file ;
- queue : liste des voitures dans une file.

Formule de base :
    penalty = CONGESTION_VEHICLE_PENALTY

Ajouts :
- si BRAKING :
      penalty += CONGESTION_BRAKING_PENALTY
- si STOPPED :
      penalty += CONGESTION_STOPPED_PENALTY
- si waiting_at_light :
      penalty += CONGESTION_QUEUE_PENALTY
- si speed < 1.0 :
      penalty += CONGESTION_BRAKING_PENALTY

Penalite d'arc :
    edge_penalties[(seg_from, seg_to)] += penalty

Penalite de route :
    road_penalties[seg_road_id] += penalty * CONGESTION_ROAD_FACTOR

Penalite de file :
    edge_penalties[(seg_from, light_nid)] += len(queue) * CONGESTION_QUEUE_PENALTY

Fonction interne penalty(edge) :
Retourne :
    edge_penalties[(edge.from_node, edge.to_node)] + road_penalties[edge.road_id]

Effet :
Les nouveaux chemins evitent les zones deja encombrees quand une alternative
existe.

8. BOUCLE DE MISE A JOUR

8.1 update(dt)
--------------
Role :
Mettre a jour tous les vehicules actifs.

Variables :
- to_remove : liste des vehicules a supprimer ;
- vid : identifiant du vehicule ;
- v : vehicule courant.

Etapes :
1. Ignore les vehicules ARRIVED ou NO_PATH.
2. Ajoute dt a travel_time.
3. Diminue queue_cooldown.
4. Appelle _update_vehicle.
5. Si le vehicule arrive, il est marque pour suppression.
6. Supprime les vehicules arrives.
7. Retire ces vehicules des files.
8. Libere leurs reservations.
9. Corrige les chevauchements sur meme segment.
10. Corrige les chevauchements entre segments consecutifs.

8.2 _update_vehicle(v, dt)
--------------------------
Role :
Faire avancer un vehicule pendant dt, en sous-etapes.

Variables :
- remaining : temps restant a simuler ;
- segs : nombre de segments traverses ;
- steps : nombre de sous-etapes ;
- target_nid : prochain noeud cible ;
- target_node : objet noeud cible ;
- dist : distance actuelle au noeud cible ;
- speed_cap : vitesse maximale probable pendant remaining ;
- step_dt : temps de sous-etape ;
- prev_idx : path_index avant _tick ;
- before : valeur de remaining avant _tick ;
- used_dt : temps reellement utilise ;
- crossed : indique si un noeud a ete franchi.

Formule speed_cap :
    speed_cap = max(MIN_SPEED, min(v.max_speed, v.speed + MAX_ACCEL * remaining))

Formule step_dt :
    step_dt = min(remaining, dist / max(speed_cap, MIN_SPEED))

Protection :
- remaining > 1e-9 ;
- segs < MAX_SEGS_PER_TICK ;
- steps < MAX_SEGS_PER_TICK * 3.

Pourquoi :
Cela evite qu'une voiture saute plusieurs noeuds d'un coup quand la simulation
est acceleree.

8.3 _tick(v, target_nid, target_node, dist, dt)
-----------------------------------------------
Role :
Faire une decision de conduite elementaire.

Ordre de decision :
1. _handle_queue : si la voiture est en file, la file prend le controle.
2. desired = v.max_speed.
3. Reduction par distance au leader :
       _speed_for_gap(_gap_to_leader(...), v.max_speed)
4. Reduction par feu :
       _light_approach_speed(v)
5. Reduction par intersection :
       _intersection_token_speed(...)
6. Application acceleration/freinage :
       _apply_speed(v, desired, dt)
7. Garde rouge/orange :
       _red_light_stop_guard(...)
8. Mouvement physique :
       _move_vehicle(...)

Variable desired :
Vitesse cible finale.
Elle est le minimum de toutes les contraintes.

9.1 _gap_to_leader(v, target_nid, my_dist)
------------------------------------------
Role :
Trouver la distance libre devant v.

Variables :
- best : meilleur espace libre trouve, initialise a math.inf ;
- target_node : noeud cible ;
- fn_node : noeud de depart du segment ;
- tn_node : noeud cible du segment ;
- ux, uy : direction du segment ;
- has_dir : True si la direction est valide ;
- next_nid : noeud apres target_nid ;
- other : autre vehicule inspecte ;
- od : distance de other au noeud cible ;
- same_place_leader : departage si deux voitures sont au meme endroit ;
- d : distance GPS entre v et other.

Cas 1 : meme segment, meme sens
Si other est plus proche du noeud cible que v, alors other est devant.

Formule de gap :
    my_dist - od - VEHICLE_LENGTH

Cas 2 : vehicule sur le segment suivant
La fonction regarde si une voiture est juste apres le prochain noeud, dans la
direction de v.
Elle utilise _dot_to_other_meters pour confirmer que l'autre est devant.

Cas 3 : vehicule arrete ou lent sur segment suivant
Si other.speed < 1.0 et qu'il est proche, v ralentit avant d'entrer.

Retour :
- meilleur gap trouve ;
- math.inf si aucune voiture devant.

10. FEUX ET ARRET AU ROUGE/ORANGE

10.1 _light_approach_speed(v)
-----------------------------
Role :
Calculer une vitesse limite si un feu rouge/orange est devant.

Variables :
- lookahead : profondeur de recherche, de 0 a 2 ;
- idx : index dans le chemin ;
- nid : noeud teste ;
- from_nid : noeud depuis lequel la voiture approche ce feu ;
- light : feu trouve pour cette approche ;
- ls : etat du feu ;
- node : noeud du feu ;
- d : distance le long du chemin jusqu'au feu ;
- eff : distance utile apres retrait de STOP_LINE_DIST ;
- ratio : proportion de vitesse autorisee.

Regles :
- si la voiture est deja dans la file de ce feu, la fonction laisse _handle_queue
  gerer ;
- si le feu ne concerne pas cette approche, il est ignore ;
- si le feu est vert, il est ignore ;
- si le feu est rouge/orange et proche, la vitesse est reduite.

Formule :
    eff = max(0.0, d - STOP_LINE_DIST)
    ratio = eff / max(1.0, LIGHT_BRAKE_DIST - STOP_LINE_DIST)
    return v.max_speed * ratio

10.2 _light_for_approach(node_id, from_node)
--------------------------------------------
Role :
Retourner le feu seulement s'il concerne l'approche from_node -> node_id.

Variables :
- light : feu au noeud node_id.

Retour :
- None si from_node vaut -1 ;
- None si aucun feu ;
- None si le feu ne controle pas from_node ;
- light sinon.

Importance :
Cette fonction evite qu'une voiture soit guidee par le mauvais feu dans un
carrefour.

10.3 _path_distance_to_index(v, target_index)
---------------------------------------------
Role :
Calculer la distance le long du chemin jusqu'a un index futur.

Variables :
- first_node : prochain noeud actuel ;
- total : distance cumulee ;
- idx : index de boucle ;
- a, b : deux noeuds consecutifs.

Calcul :
1. Distance de la position actuelle vers path[path_index].
2. Ajout de chaque segment jusqu'a target_index.

Formule :
    total += haversine(a.lat, a.lon, b.lat, b.lon)

Retour :
- distance en metres ;
- math.inf si l'index est invalide.

10.4 _red_light_stop_guard(v, target_nid, dist, dt)
---------------------------------------------------
Role :
Barriere finale contre le franchissement d'un feu rouge/orange.

Variables :
- light : feu qui concerne l'approche ;
- move : distance que la voiture voudrait parcourir ;
- max_move_before_line : distance maximale possible avant la ligne d'arret.

Regles :
- si la voiture est en file, la file gere deja l'arret ;
- si le feu ne concerne pas la voiture, aucune action ;
- si le feu est vert, aucune action ;
- si la voiture est trop proche, elle est replacee a STOP_LINE_DIST ;
- si son mouvement depasserait la ligne, elle est replacee et arretee.

Formules :
    move = v.speed * dt
    max_move_before_line = max(0.0, dist - STOP_LINE_DIST)

Effet :
Impossible de franchir volontairement un feu rouge/orange qui concerne la
voiture.

===============================================================================
11. INTERSECTIONS ET PRIORITES
===============================================================================

11.1 _intersection_token_speed(v, target_nid, dist, dt)
-------------------------------------------------------
Role :
Decider si v peut entrer dans une intersection.

Variables :
- incoming : sources entrantes du noeud ;
- owners : vehicules ayant deja une reservation ;
- has_conflict : True si une reservation existante est incompatible.

Regles :
1. Si la voiture est en file, pas de token d'intersection.
2. Si le noeud a moins de 2 entrees, pas besoin.
3. Si ce n'est pas une vraie intersection, pas besoin.
4. Si la voiture est loin, elle ne reserve pas.
5. Si le feu de son approche est rouge/orange, elle ne reserve pas.
6. Si elle a deja reserve ce noeud, elle avance.
7. Si aucun conflit et pas de priorite a ceder, elle reserve.
8. Sinon elle ralentit avec _intersection_yield_speed.

11.2 _intersection_yield_speed(v, dist)
---------------------------------------
Role :
Calculer une vitesse lente quand la voiture cede a une intersection.

Variables :
- ratio : proportion de distance avant le point d'arret.

Formule :
    ratio = (dist - INTER_CLEAR_DIST) / (INTER_RESERVE_DIST - INTER_CLEAR_DIST)
    vitesse = v.max_speed * min(ratio, 0.18)

Si dist <= INTER_CLEAR_DIST + 0.5 :
    vitesse = 0

11.3 _active_token_owners(node_id, requester_id=-1)
---------------------------------------------------
Role :
Retourner les vehicules qui possedent encore une reservation valide.

Variables :
- owners : set des vehicle_id reserves ;
- active : liste des vehicules actifs ;
- stale_ids : reservations mortes a nettoyer ;
- owner_id : id inspecte ;
- owner : vehicule correspondant ;
- stale : True si la reservation n'est plus valide.

Une reservation est stale si :
- le vehicule n'existe plus ;
- il est arrive ;
- son reserved_node n'est plus node_id ;
- son path_index est invalide ;
- son prochain noeud n'est plus node_id.

11.4 _approach_allowed_by_light(v, target_nid)
----------------------------------------------
Role :
Dire si le feu autorise v a approcher target_nid.

Regle :
- pas de feu concerne : True ;
- feu concerne : True seulement si GREEN.

11.5 _must_yield_at_intersection(v, target_nid, my_dist)
--------------------------------------------------------
Role :
Decider si v doit ceder a une autre voiture.

Variables :
- target_node : noeud d'intersection ;
- my_turn : mouvement de v ;
- other : autre vehicule ;
- other_dist : distance de other au carrefour ;
- other_turn : mouvement de other.

Regles :
1. Ignore les voitures non pertinentes.
2. Si v tourne a gauche et qu'un vehicule arrive en face tout droit/droite, v
   cede.
3. Si une voiture arrive par la droite, v cede.
4. Si une autre voiture est nettement plus proche du carrefour, v cede.

Formules de seuil :
    other_dist <= my_dist + 8.0
    other_dist <= my_dist + 6.0
    other_dist + 2.0 < my_dist

11.6 _turn_kind(v, target_nid)
------------------------------
Role :
Classer le mouvement : straight, left, right ou end.

Variables :
- from_node : noeud d'arrivee avant carrefour ;
- inter_node : noeud du carrefour ;
- next_node : noeud apres carrefour ;
- in_ux, in_uy : direction entrante ;
- out_ux, out_uy : direction sortante ;
- dot : produit scalaire ;
- cross : produit vectoriel 2D ;
- angle : angle signe en degres.

Formules :
    dot = in_ux * out_ux + in_uy * out_uy
    cross = in_ux * out_uy - in_uy * out_ux
    angle = degrees(atan2(cross, dot))

Regles :
- si abs(angle) <= 30 : straight ;
- si angle > 0 : left ;
- sinon : right.

11.7 _is_oncoming_approach(v, other)
------------------------------------
Role :
Dire si v et other arrivent en face l'un de l'autre.

Variables :
- vux, vuy : direction de v ;
- oux, ouy : direction de other.

Formule :
    dot = vux * oux + vuy * ouy

Regle :
    dot <= -0.70
signifie directions opposees.

11.8 _next_after_intersection(v)
--------------------------------
Role :
Retourner le noeud apres l'intersection.

Retour :
- path[path_index + 1] si existe ;
- -1 sinon.

11.9 _movements_conflict(v, other, target_nid)
----------------------------------------------
Role :
Dire si deux trajectoires dans le carrefour sont incompatibles.

Variables :
- my_next : sortie de v ;
- other_next : sortie de other ;
- my_turn : virage de v ;
- other_turn : virage de other.

Regles :
- meme vehicule : pas conflit ;
- meme seg_from : pas conflit ici, car distance de securite gere deja ;
- meme sortie : conflit ;
- vehicules en face :
    gauche contre tout droit/droite/end = conflit ;
    tout droit contre tout droit = compatible ;
    tout droit contre droite = compatible ;
- autres cas : conflit par prudence.

11.10 _is_other_on_right(v, other, target_nid)
----------------------------------------------
Role :
Detecter la priorite a droite.

Variables :
- inter_node : noeud carrefour ;
- ux, uy : direction de v ;
- ox, oy : vecteur depuis le carrefour vers other ;
- norm : longueur de ce vecteur ;
- right_x, right_y : vecteur droite de v.

Formules :
    ox = (other.lon - inter.lon) * M_PER_DEG_LON
    oy = (other.lat - inter.lat) * M_PER_DEG_LAT
    norm = sqrt(ox * ox + oy * oy)
    right_x = uy
    right_y = -ux
    score = (ox / norm) * right_x + (oy / norm) * right_y

Regle :
    score >= cos(45 degres)
donc other est dans le secteur droit.

11.11 _token_acquire(v, node_id)
--------------------------------
Role :
Donner une reservation d'intersection a v.

Variables :
- owners : set de proprietaires d'une ancienne reservation.

Etapes :
1. Si v reservait un autre noeud, l'ancien token est retire.
2. v.reserved_node = node_id.
3. vehicle_id est ajoute dans _node_tokens[node_id].

11.12 _token_release(v)
-----------------------
Role :
Liberer la reservation de v.

Etapes :
1. Cherche l'ensemble owners du noeud reserve.
2. Retire v.vehicle_id.
3. Supprime l'entree si l'ensemble devient vide.
4. Met v.reserved_node a -1.

11.13 _get_incoming_sources(node_id)
------------------------------------
Role :
Retourner les noeuds entrants vers node_id.

Retour :
- set vide si _incoming_cache est None ;
- _incoming_cache[node_id] sinon.

11.14 _is_real_intersection_node(node_id)
-----------------------------------------
Role :
Eviter de traiter un simple noeud de forme comme un carrefour.

Variables :
- neighbors : voisins entrants et sortants.

Regle :
    len(neighbors) >= 3
signifie vraie intersection.

12. FILES D'ATTENTE AUX FEUX
===============================================================================

12.1 _handle_queue(v, target_nid, dist, dt)
-------------------------------------------
Role :
Decider si la logique de file prend le controle de la voiture.

Cas deja en file :
- verifie que la voiture est encore dans _queues ;
- si feu vert, appelle _queue_release ;
- sinon appelle _queue_hold.

Cas pas encore en file :
La voiture rejoint une file seulement si :
- pas de cooldown ;
- le noeud cible a un feu ;
- v.seg_to == target_nid ;
- v.seg_from est valide ;
- dist <= QUEUE_JOIN_DIST ;
- feu rouge ou orange ;
- feu controle bien v.seg_from.

12.2 _queue_join(v, light_nid)
------------------------------
Role :
Ajouter v dans la bonne file.

Variables :
- captured_seg_from : segment d'approche fige ;
- key : (light_nid, captured_seg_from) ;
- q : liste de vehicules de cette file.

Etapes :
1. Verifie seg_from.
2. Retire d'une ancienne file si besoin.
3. Libere le token d'intersection.
4. Compacte la file.
5. Verifie que la place tient sur le segment.
6. Renseigne les champs queue_*.
7. Ajoute vehicle_id.
8. Compacte encore.
9. Enregistre un vehicule en attente dans light_manager.

12.3 _queue_remove(v)
---------------------
Role :
Retirer v de sa file.

Variables :
- key : cle de file ;
- q : liste de vehicules ;
- idx : position de v dans la file ;
- ov : vehicule derriere a reindexer.

Effets :
- retire vehicle_id de q ;
- recalcule les queue_index ;
- remet queue_light_node, queue_index, queue_seg_from a -1 ;
- waiting_at_light = False ;
- queue_release_timer = 0 ;
- supprime la file si vide.

12.4 _queue_compact(key)
------------------------
Role :
Nettoyer et retrier une file selon la distance reelle au feu.

Variables :
- light_nid, seg_from : composants de key ;
- light_node : noeud du feu ;
- q : ancienne liste ;
- live : vehicules encore valides ;
- vid : identifiant inspecte ;
- ov : vehicule inspecte.

Tri :
    live.sort(key=(distance_au_feu, vehicle_id))

Effet :
La voiture la plus proche du feu devient queue_index 0.

12.5 _queue_slot_fits(light_nid, seg_from, slot_index)
------------------------------------------------------
Role :
Verifier que la place slot_index tient sur le segment.

Variables :
- light_node ;
- origin_node ;
- seg_len ;
- target_dist.

Formule :
    target_dist = STOP_LINE_DIST + slot_index * QUEUE_SLOT

Regle :
    target_dist <= max(STOP_LINE_DIST, seg_len - 0.5)

12.6 _queue_hold(v, dt)
-----------------------
Role :
Maintenir v a sa position de file.

Variables :
- light_nid : feu de la file ;
- key : cle de file ;
- k : indice dans la file ;
- light_node : noeud du feu ;
- dist_to_light : distance actuelle au feu ;
- target_dist : distance souhaitee au feu ;
- gap : distance restante avant la place ;
- v_safe : vitesse sure ;
- desired : vitesse cible ;
- move : distance parcourue pendant dt ;
- r : ratio d'interpolation.

Formules :
    target_dist = STOP_LINE_DIST + k * QUEUE_SLOT
    gap = dist_to_light - target_dist
    v_safe = sqrt(2 * MAX_DECEL * max(0, gap - 0.5))
    desired = min(v.max_speed * 0.35, v_safe)
    move = v.speed * dt
    r = move / dist_to_light

Interpretation de v_safe :
Formule issue de :
    v^2 = 2 * a * d
Elle donne la vitesse maximale permettant encore de s'arreter avant la place.

12.7 _queue_release(v, dt)
--------------------------
Role :
Liberer les voitures progressivement au feu vert.

Constantes locales :
- REACTION_HEAD = 0.8 ;
- REACTION_NEXT = 1.0.

Variables :
- key ;
- k : position dans la file ;
- q : file ;
- pred_id : identifiant du vehicule precedent ;
- pred : vehicule precedent.

Regles :
- premier vehicule : sort apres 0.8 s ;
- vehicule suivant : attend que le precedent sorte, puis 1.0 s ;
- apres sortie : queue_cooldown = QUEUE_RELEASE_COOLDOWN.

12.8 _place_at_slot(v, light_nid, target_dist)
----------------------------------------------
Role :
Placer v exactement a target_dist metres du feu.

Variables :
- light_node ;
- origin_node ;
- seg_len ;
- ux, uy ;
- d : distance reellement appliquee.

Formules :
    d = max(STOP_LINE_DIST * 0.5, min(target_dist, seg_len - 0.5))
    v.lat = light_node.lat - uy * (d / M_PER_DEG_LAT)
    v.lon = light_node.lon - ux * (d / M_PER_DEG_LON)

13. DEPLACEMENT PHYSIQUE ET ANTI-BLOCAGE
===============================================================================

13.1 _move_vehicle(v, target_node, dist, dt)
--------------------------------------------
Role :
Deplacer v vers target_node.

Variables :
- move : distance que la voiture veut parcourir ;
- used_dt : temps reel necessaire pour atteindre le noeud.

Formule :
    move = v.speed * dt

Si move atteint le noeud :
1. Calcule used_dt.
2. Verifie _next_segment_has_space.
3. Si la sortie est bouchee, replace la voiture avant le noeud et l'arrete.
4. Libere le token si le noeud etait reserve.
5. Place la voiture au noeud.
6. Incremente path_index.
7. Si fin du chemin : ARRIVED.
8. Sinon : _init_segment.

Si move ne suffit pas :
Interpolation :
    r = move / dist
    v.lat += (target_node.lat - v.lat) * r
    v.lon += (target_node.lon - v.lon) * r

13.2 _next_segment_has_space(v)
-------------------------------
Role :
Verifier que le segment suivant peut recevoir la voiture.

Variables :
- next_from : noeud d'entree du segment suivant ;
- next_to : noeud de sortie ;
- origin_node ;
- target_node ;
- seg_len : longueur du segment suivant ;
- occupants : voitures deja sur le segment suivant ;
- closest_from_origin : voiture la plus proche de l'entree ;
- usable_len : longueur utile ;
- capacity : capacite theorique ;
- max_occupants : seuil de remplissage accepte ;
- near_entry_limit : zone proche de l'entree.

Regles :
- si aucun occupant : True ;
- si une voiture est a moins de QUEUE_SLOT de l'entree : False ;
- si le segment est rempli au-dela de RECEIVING_SEGMENT_FILL_RATIO : False ;
- si une voiture lente est proche de l'entree : False.

Formules :
    usable_len = max(QUEUE_SLOT, seg_len - STOP_LINE_DIST)
    capacity = max(1, int(usable_len / QUEUE_SLOT))
    max_occupants = ceil(capacity * RECEIVING_SEGMENT_FILL_RATIO)
    near_entry_limit = min(seg_len, QUEUE_SLOT * 2.0)

Effet :
Evite d'envoyer des voitures dans une sortie deja bouchee.

13.3 _resolve_same_segment_overlaps()
-------------------------------------
Role :
Corriger les chevauchements sur un meme segment.

Variables :
- groups : voitures groupees par (seg_from, seg_to) ;
- cars : liste des voitures d'un segment ;
- target_node ;
- prev_dist : distance au noeud de la voiture precedente ;
- prev_speed : vitesse de la voiture precedente ;
- car_dist ;
- min_dist.

Tri :
    cars.sort(key=(distance_au_noeud_cible, vehicle_id))

Regle :
Chaque voiture derriere doit etre au moins a :
    prev_dist + QUEUE_SLOT

Si ce n'est pas le cas, elle est replacee avec _place_on_current_segment.

13.4 _resolve_adjacent_segment_overlaps()
-----------------------------------------
Role :
Corriger les chevauchements de part et d'autre d'un noeud.

Variables :
- by_segment : voitures groupees par segment ;
- follower : voiture avant le noeud ;
- shared_node : noeud commun ;
- next_node : segment apres le noeud ;
- shared : objet noeud commun ;
- best_leader_dist : leader le plus proche apres le noeud ;
- best_leader_speed ;
- leader ;
- follower_dist ;
- path_gap ;
- target_dist.

Formule :
    path_gap = follower_dist + best_leader_dist

Regle :
Si path_gap < QUEUE_SLOT, le follower est replace avant le noeud.

13.5 _place_on_current_segment(v, target_dist)
----------------------------------------------
Role :
Placer v a target_dist metres du noeud cible de son segment.

Variables :
- target_node ;
- origin_node ;
- seg_len ;
- ux, uy ;
- upper : distance maximale autorisee ;
- d : distance appliquee.

Formules :
    upper = max(0.5, seg_len - 0.5)
    d = max(0.5, min(target_dist, upper))
    v.lat = target_node.lat - uy * (d / M_PER_DEG_LAT)
    v.lon = target_node.lon - ux * (d / M_PER_DEG_LON)

Retour :
    d

16. CHAINE COMPLETE DE DECISION D'UNE VOITURE
===============================================================================

1. spawn_vehicle cree une voiture.
2. Le chemin est calcule avec Dijkstra + penalites de congestion.
3. _init_segment prepare le premier segment.
4. A chaque update, _update_vehicle decoupe le temps en sous-etapes.
5. _tick calcule une vitesse cible.
6. _handle_queue peut prendre le controle si la voiture attend a un feu.
7. _gap_to_leader limite la vitesse selon le vehicule devant.
8. _light_approach_speed limite la vitesse selon un feu rouge/orange.
9. _intersection_token_speed limite la vitesse selon les priorites.
10. _apply_speed applique acceleration ou freinage.
11. _red_light_stop_guard empeche le franchissement rouge/orange.
12. _move_vehicle deplace la voiture.
13. _next_segment_has_space evite d'entrer dans une sortie bouchee.
14. Les corrections d'overlap nettoient les positions.
15. Les statistiques exposent l'etat global.

===============================================================================
18. CONCLUSION
===============================================================================

vehicle.py fonctionne comme un moteur de decision multi-contraintes.

Chaque vehicule choisit un chemin, puis a chaque instant sa vitesse est limitee
par :
- la vitesse autorisee ;
- la voiture devant ;
- les feux ;
- les files ;
- les intersections ;
- la place disponible dans la sortie ;
- les corrections de securite.

Les formules importantes sont toutes basees sur :
- distances GPS converties en metres ;
- produits scalaires ;
- produits vectoriels ;
- interpolation lineaire ;
- freinage avec v^2 = 2ad ;
- vitesse proportionnelle a l'espace libre ;
- seuils de securite.

Le fichier est donc responsable de la fluidite, de la securite et de la
coherence des voitures dans la simulation.
